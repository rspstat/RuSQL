# RuSQL 추천 목록 (남은 항목만, R47 이후 · 2026-10-22)

완료된 항목은 뺐습니다(R44~R47에서 끝낸 것은 `DATE.md`에 있습니다). 현재 상태·추천도·비용은 코드와 엔진에 직접 돌려 보고 매긴 값입니다.

- **현재 상태:** `일부`(일부만 있음) · `없음`
- **추천도:** ★ 다섯 개. 기준은 실사용 가치 + 발표 임팩트 + 비용 대비 효과입니다. 졸업작품 마감(11월 말)까지 약 5주를 전제로 합니다.
- **비용:** 제가 구현하고 검증(코퍼스 비교, 심은 버그, 전체 시험, 문서)까지 마치는 데 걸리는 시간입니다. 하 ≈ 2~4시간, 중 ≈ 하루, 상 ≈ 2~4일. 빌드와 전체 시험 한 바퀴가 약 35분이라 헤더를 건드리는 변경은 여러 바퀴가 듭니다. **프론트(UI)는 자동 시험이 없어서 눈으로 확인하는 시간이 따로 붙습니다.**

## 1. 문법 추가 (지금은 오류가 나는 것)

| 항목 | 현재 상태 | 추천도 | 비용 | 근거 |
|---|---|---|---|---|
| `INSERT INTO t () VALUES ()` | 없음 | ★★★ | 하~중 | 파서와 빈 행 삽입(기본값·AUTO_INCREMENT) 경로입니다. |
| `RANGE BETWEEN 5 PRECEDING AND …` (값 기준 프레임 오프셋) | 일부 (피어는 R47에서 고침, 오프셋은 행 수로 읽음) | ★★ | 하~중 | 숫자·날짜 ORDER BY 키의 값 범위로 프레임을 잡아야 합니다. |
| `DEFAULT (식)` | 없음 | ★★★ | 중 | 다른 열을 읽는 기본값 평가가 새로 필요합니다. MySQL 8 덤프에 나옵니다. |
| `WITH ROLLUP` | 없음 | ★★★ | 중 | 소계 행 생성과 `NULL` 표시가 필요합니다. |
| `SELECT @x := 식` | 없음 (R43에서 일부러 오류로 둠) | ★★★ | 중 | 행마다 평가하는 순서와 세션 변수 상태가 걸립니다. |
| `SIGNAL` | 없음 | ★★★ | 하~중 | 루틴에서 오류를 던지는 기본 수단입니다. |
| `CREATE TEMPORARY TABLE` | 없음 | ★★★ | 중~상 | 세션별 이름 공간과 연결 종료 시 정리가 필요합니다. |
| 생성 열 `GENERATED ALWAYS AS` | 없음 | ★★★ | 상 | 읽기 경로, 인덱스, ALTER까지 걸립니다. |
| 커서·`HANDLER` | 없음 | ★★★ | 상 | 저장 루틴 해석기에 상태가 새로 필요합니다. |
| 한 열에 FK 둘 이상, 여러 열 FK | 없음 (같은 열에 더하면 앞의 것을 덮어씀, 여러 열 FK는 오류) | ★★ | 중~상 | 열마다 FK 하나라는 저장 구조를 바꿔야 합니다. ERD 편집기는 이미 FK가 있는 열을 경고합니다. |
| `JSON_ARRAYAGG` | 없음 (`JSON_AGG`는 있음) | ★★ | 하 | 별칭입니다. `JSON_OBJECTAGG`는 하~중. |
| `UPDATE IGNORE` | 없음 | ★★ | 중 | 오류 난 행만 건너뛰는 의미가 새로 필요합니다. |
| `ALTER … ADD/DROP PRIMARY KEY` | 없음 | ★★ | 중 | 인덱스·참조 재구성이 걸립니다. |
| `END LOOP 라벨`, `DECLARE … DEFAULT 식` | 없음 | ★★ | 하 | 파서 수준입니다. |

## 2. 기능 추가

| 항목 | 현재 상태 | 추천도 | 비용 | 근거 |
|---|---|---|---|---|
| `KILL` | 없음 | ★★★ | 하~중 | R46에서 취소 확인점(루프의 시계 확인)이 생겨 비용이 줄었습니다. 세션마다 "중단" 표시를 두고 같은 확인점에서 읽으면 됩니다. |
| 느린 쿼리 로그 | 없음 | ★★★ | 중 | 임계값을 넘은 문장을 기록하고 `SHOW`로 보여 주면 됩니다. `TRACE`의 단계 기록을 쓸 수 있습니다. |
| `EXPLAIN ANALYZE` 더 확장 | 일부 (단계별 행 수·시간·비율, `TRACE`는 커밋 단계까지) | ★★★ | 중~상 | 남은 것은 조인 안의 알고리즘별, 하위 질의별 시간입니다. |
| `FULLTEXT` / `MATCH … AGAINST` | 없음 | ★★★ | 상 | 검색 데모는 강하지만 역색인과 점수 계산이 큽니다. |
| `USE INDEX` / `FORCE INDEX` | 없음 | ★★ | 중 | 플래너에 힌트를 전달해야 합니다. |
| `JSON_TABLE` | 없음 | ★★ | 상 | 쓰임새에 비해 큽니다. |
| `LOAD DATA` / `INTO OUTFILE` | 없음 (UI의 CSV 가져오기·내보내기는 있음) | ★★ | 중 | 서버 파일 접근 보안 문제가 있고 UI가 이미 해결합니다. |
| 없는 함수 묶음 (`INET_*`, `UUID_TO_BIN`, `CONVERT_TZ` …) | 없음 | ★★ | 하 | 하나씩은 싸지만 가치가 작습니다. |
| `CREATE EVENT` | 없음 | ★ | 중~상 | 스케줄러가 필요한데 쓰임새가 작습니다. |

## 6. 발표 대비

| 항목 | 현재 상태 | 추천도 | 비용 | 근거 |
|---|---|---|---|---|
| MCP 시연 대본·리허설 | 일부 (`DEMO.md` 4단계에 한 줄, "자동 검증 못함") | ★★★★★ | 하 | 대본을 쓰고 Claude Desktop에서 직접 한 번 돌려 봐야 합니다. `run_script` 미리보기(영향 행 확인 후 커밋)가 좋은 장면입니다. 연결은 직접 해 보셔야 합니다. |
| 크래시 복구 데모 | 일부 (`DEMO.md` 3단계에 `taskkill` 수동 절차) | ★★★★ | 하~중 | "강제 종료 → 재시작 → 복구 시간" 버튼으로 만들면 됩니다. |
| 락·데드락 데모 | 일부 (락·대기·교착 패널은 있음, 대본은 없음) | ★★★★ | 하 | 두 세션으로 락 대기와 교착을 일으키는 대본만 쓰면 패널이 실시간으로 보여 줍니다. |

| 한 문장의 여행에 보여 줄 문장 고르기 | 일부 (재생기는 있음) | ★★★ | 하 | JOIN+GROUP BY, INSERT의 커밋 단계 같은 3~4문장을 골라 두면 됩니다. |

| 최적화 전후 속도 | 일부 (정적 `speedup_chart.png`, Benchmark 패널) | ★★★ | 하 | 이미 있는 데이터를 애니메이션으로 바꾸면 됩니다. |
| RuSQL vs MySQL 분할 화면 | 없음 | ★★★ | 중 | 발표장에 MySQL이 떠 있어야 해서 불안정합니다. |

## 추천 순서 (약 5주)

1. **먼저 (하루 안팎):** MCP 시연 대본·리허설, 락·데드락 시연 대본, `list_locks`·`get_table_stats`.
2. **발표의 뼈대:** 크래시 복구 버튼, EXPLAIN 단계 막대, 여정에 보여 줄 문장 고르기.
3. **엔진:** `KILL`(R46에서 생긴 취소 확인점 위에), `suggest_indexes`.
4. **시간이 되면:** MVCC 나란히 보기, `WITH ROLLUP`, 남은 한계 정리, `INSERT INTO t () VALUES ()`, 느린 쿼리 로그.
5. **미루거나 하지 않는 것:** `FULLTEXT`, 커서·`HANDLER`, 생성 열, 한 열에 FK 여러 개, `caching_sha2_password`, TLS, WAL 복제.
