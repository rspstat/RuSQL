# RuSQL 추천 목록 (R46 이후, 2026-10-21 · 코드로 현황을 확인한 판)

이 판은 엔진에 실제로 SQL을 돌려 보고, 프론트·MCP·서버 코드를 읽어서 항목마다 현재 상태를 확인한 뒤 추천도와 비용을 매겼습니다. R46에서 다섯 항목을 끝냈고(아래 "R46에서 끝낸 것"), 그 과정에서 새로 알게 된 것(집계 위 윈도가 오류가 아니라 빈 값을 돌려줌, 한 열에 FK 하나만 가능)을 항목에 반영했습니다.

- **현재 상태:** `있음`(이미 구현) · `일부`(일부만 있음) · `없음`
- **추천도:** ★ 다섯 개. 기준은 실사용 가치 + 발표 임팩트 + 비용 대비 효과입니다. 졸업작품 마감(11월 말)까지 약 5주를 전제로 합니다.
- **비용:** 제가 구현하고 검증(코퍼스 비교, 심은 버그, 전체 시험, 문서)까지 마치는 데 걸리는 시간입니다. 하 ≈ 2~4시간, 중 ≈ 하루, 상 ≈ 2~4일. 이 프로젝트는 빌드와 전체 시험 한 바퀴가 약 35분이라, 헤더를 건드리는 변경은 여러 바퀴가 듭니다. **프론트(UI)는 자동 시험이 없어서 눈으로 확인하는 시간이 따로 붙습니다.**

## R46에서 끝낸 것

| 항목 | 결과 |
|---|---|
| 윈도 단축형 | `ROWS UNBOUNDED PRECEDING`·`ROWS 2 PRECEDING`, `WINDOW w AS (…)`, `OVER w`, `OVER (w ORDER BY …)`. 파서가 토큰 단계에서 풀어 쓰는 방식이라 AST·실행기는 그대로. 코퍼스 26문장 MySQL과 차이 0 |
| `MAX_EXECUTION_TIME` | 힌트와 `SET max_execution_time`. 넘으면 오류 3024, 세션은 그대로. 문장을 밖에서 끊지 않고 루프가 시계를 확인하는 방식. 코퍼스 17문장 차이 0. 병렬 스캔의 작업 스레드는 확인하지 않음 |
| ERD에서 FK 편집 + DDL 미리보기 | 관계선을 누르거나 `＋ Relationship`. 고르는 대로 아래에 `ALTER TABLE …`이 그대로 보이고 `Apply` 전에는 실행하지 않음. 수정은 DROP+ADD가 한 ALTER. **만들다가 엔진 버그 둘을 찾아 고침**: 부모를 데이터베이스 없이 쓴 `ADD FOREIGN KEY` 뒤 자식 표의 모든 INSERT 실패, 제약 이름 미저장(`DROP FOREIGN KEY <이름>` 불가). `information_schema.referential_constraints` 신설. 코퍼스 22문장 차이 0 |
| MCP `run_script` | 한 연결·한 트랜잭션, 문장별 결과 JSON, 미리보기(ROLLBACK)와 `commit=True`(전부 되거나 전혀 안 됨). DDL은 미리보기로 거절. 살아 있는 서버로 17가지 확인. 도구 26개 |
| SQL 한 문장의 여행 | 엔진 `TRACE <문장>`(실제 실행 + 단계표) + 에디터의 Journey 버튼(기록 재생, 일시정지·한 단계씩·0.5~4x, 단계별 시간 막대) |

심은 버그 12종을 모두 잡았고 전체 시험 781 케이스 / 1,505,497 assertions가 Release 기본과 `RUSQL_DML_INDEX_MIN_ROWS=0`으로 통과했습니다. **프론트는 `tsc`·`vite build`와 `invoke`를 모형으로 바꾼 헤드리스 Chrome 화면까지 확인했고, 실제 Tauri 앱에서 눌러 본 것은 아닙니다.**

## 1. 문법 추가 (지금은 오류가 나는 것)

| 항목 | 현재 상태 | 추천도 | 비용 | 근거 |
|---|---|---|---|---|
| 윈도 단축형 (`OVER w`/`WINDOW`, `ROWS UNBOUNDED PRECEDING`) | **있음 (R46)** | — | — | |
| 집계 위 윈도 (`RANK() OVER (ORDER BY SUM(x) DESC)`) | 없음 — **오답** (`SUM(i) OVER (…) … GROUP BY g, i`가 오류가 아니라 빈 값을 돌려줌, `SUM(SUM(i)) OVER ()`는 오류) | ★★★★ | 중~상 | 리포트 쿼리에 가장 흔하고, 지금은 조용히 틀립니다. 집계 뒤에 윈도를 평가하도록 순서를 바꿔야 합니다. |
| `INSERT INTO t () VALUES ()` | 없음 | ★★★ | 하~중 | 파서와 빈 행 삽입(기본값·AUTO_INCREMENT) 경로입니다. |
| `JSON_ARRAYAGG` | 없음 (`JSON_AGG`는 있음) | ★★ | 하 | 별칭입니다. `JSON_OBJECTAGG`는 하~중. |
| `DEFAULT (식)` | 없음 | ★★★ | 중 | 다른 열을 읽는 기본값 평가가 새로 필요합니다. MySQL 8 덤프에 나옵니다. |
| 생성 열 `GENERATED ALWAYS AS` | 없음 | ★★★ | 상 | 읽기 경로, 인덱스, ALTER까지 걸립니다. |
| `WITH ROLLUP` | 없음 | ★★★ | 중 | 소계 행 생성과 `NULL` 표시가 필요합니다. |
| `SELECT @x := 식` | 없음 (R43에서 일부러 오류로 둠) | ★★★ | 중 | 행마다 평가하는 순서와 세션 변수 상태가 걸립니다. |
| `CREATE TEMPORARY TABLE` | 없음 | ★★★ | 중~상 | 세션별 이름 공간과 연결 종료 시 정리가 필요합니다. |
| 한 열에 FK 둘 이상, 여러 열 FK | 없음 (같은 열에 더하면 앞의 것을 덮어씀, 여러 열 FK는 오류) | ★★ | 중~상 | 열마다 FK 하나라는 저장 구조를 바꿔야 합니다. ERD 편집기는 이미 FK가 있는 열을 경고합니다. |
| `ALTER … ADD/DROP PRIMARY KEY` | 없음 | ★★ | 중 | 인덱스·참조 재구성이 걸립니다. |
| `UPDATE IGNORE` | 없음 | ★★ | 중 | 오류 난 행만 건너뛰는 의미가 새로 필요합니다. |
| `END LOOP 라벨`, `DECLARE … DEFAULT 식` | 없음 | ★★ | 하 | 파서 수준입니다. |
| `SIGNAL` | 없음 | ★★★ | 하~중 | 루틴에서 오류를 던지는 기본 수단입니다. |
| 커서·`HANDLER` | 없음 | ★★★ | 상 | 저장 루틴 해석기에 상태가 새로 필요합니다. |

## 추천 순서 (R46 이후, 약 5주)

1. **먼저 (하루 안팎):** MCP 시연 대본·리허설(`run_script` 미리보기 장면 포함), 락·데드락 시연 대본(패널이 이미 있음), `list_locks`·`get_table_stats`.
2. **발표의 뼈대:** 크래시 복구 버튼, EXPLAIN 결과 패널의 단계 막대, 한 문장의 여행에 보여 줄 문장 고르기.
3. **엔진:** **집계 위 윈도(지금은 조용히 틀린 값)**, `KILL`(이번에 생긴 취소 확인점 위에), `suggest_indexes`.
4. **시간이 되면:** MVCC 나란히 보기, `WITH ROLLUP`, 남은 한계 정리, `INSERT INTO t () VALUES ()`, 느린 쿼리 로그.
5. **미루거나 하지 않는 것:** `FULLTEXT`, 커서·`HANDLER`, 생성 열, 한 열에 FK 여러 개, `caching_sha2_password`, TLS, WAL 복제.
