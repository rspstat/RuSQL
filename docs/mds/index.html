Engine Enhancements & Optimization
Index
  • B+Tree (single / composite / clustered, ORDER=16)
  • Hash Index (USING HASH, equality O(1))
  • Covering index (Index-only scan)
  • Secondary index duplicate key array storage
  • Incremental secondary index update O(1) per row
  • No full rebuild, immediately applied on each DML
  • B+Tree range scan pruning
  • scan_from / scan_to O(log N + k)
  • range_keys BETWEEN delete optimization
  • Reverse swap_remove, no index corruption
  • row_pk_pos position index
  • DELETE PK = ? → O(1) swap_remove fast-path
  • Top-K index early termination
  • Stops immediately when condition met with ORDER BY + LIMIT
  • Numeric-aware key comparison ("10" > "9" works correctly)
Query Execution Optimization
  • Cost-based AccessPath auto-selection
  • Hash Index preferred for equality conditions
  • Join order optimization (System-R bitmask DP)
  • N≤8 DP, N>8 / OUTER JOIN → greedy fallback
  • Uncorrelated subquery HashSet materialization
  • O(1) lookup after first execution
  • Histogram selectivity estimation
  • ANALYZE TABLE → equi-depth 10-bucket
  • Parallel query execution (rayon)
  • SeqScan WHERE filter par_chunks
  • GROUP BY partial aggregation par_chunks → merge
  • ORDER BY par_sort_unstable_by
  • Hash Join probe par_iter
  • Auto for 10k+ rows / controlled by SET @rusql_parallel
  • Query result cache (LRU-512)
  • For SELECT outside transactions only
  • Immediately invalidated on DML for referenced tables
  • SELECT with subquery skips caching
Transaction & Concurrency
  • WAL binary redo log
  • WAL fsync per-commit
  • equivalent to innodb_flush_log_at_trx_commit=1
  • WAL Group Commit (leader/follower)
  • Multiple session COMMIT → single fsync batch
  • Undo Log disk persistence (_undo.log)
  • Crash Recovery (WAL Replay)
  • Checkpoint (auto 512KB / manual)
  • MVCC (_xmin / _xmax version stamps)
  • Logical delete → VACUUM → physical delete
  • AUTO VACUUM (cumulative 200 DML operations threshold)
  • Row-level Locking (shared / exclusive)
  • Deadlock detection (DFS wait-for graph)
  • 4-level isolation (RC ~ SERIALIZABLE)
  • Deferred Write
  • DML → session_tables buffer, applied on COMMIT
  • SAVEPOINT-based session-local undo
  • Per-session independent Executor
  • shared_ptr<RwLock<SharedDatabase>> shared
  • Concurrent read-only SELECT execution
  • shared lock for SELECT (no FOR UPDATE/SHARE/derived-table/CTE), exclusive lock otherwise
Buffer Pool
  • LRU eviction policy
  • Default 64p × 16KB
  • Adjustable via --buffer-pool-size N option
  • Dirty page flush (auto on eviction)
  • Cache hit rate tracking (SHOW BUFFER POOL)
  • SELECT bypasses via direct s.tables read
  • Prioritizes in-memory lookup performance
  • Cache auto-invalidated on DROP/TRUNCATE
Persistence

  • B+Tree .idx auto-saved (DML/CREATE IDX)
  • Index metadata (indexes.json)
  • Schema (including auto_increment)
  • Views (views.json)

  • Per-connection independent data directory
